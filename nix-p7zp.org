* Minimal i3/RDP VM for GUI development

** Description

Add a small, installable NixOS GUI sandbox accessed through i3 over RDP.
Keep SSH for administration and builds. Prove the experience using a real RDP
client in a virtual display, without requiring a physical monitor.

This epic charts work only. No GUI configuration or RDP smoke has been
implemented by creating these tickets. Baseline: main at 7ea9db4, which
includes the unattended install fix and a successful headless minimal smoke.

** Scope

In scope: a self-contained =examples/minimal-i3/= tree, its operator docs,
an optional locked Nix development shell for smoke dependencies, and evidence
from an ISO install and disk-only cold boot. Preserve the existing
=examples/minimal/= behavior and live installer workflow.

The GUI baseline is X11/i3, a terminal, launcher, status bar, usable fonts,
and xrdp. Start RDP sessions without a local console login. The operator can
retain VM console access for boot and recovery; RDP need not mirror it.

Retain the minimal example's documented bootstrap user and locked root
account. Use SSH tunneling for RDP without opening another guest firewall
port. This is a disposable development fixture, not a production identity
or secrets policy.

Out of scope: VM lifecycle tooling, host package installation, secrets or
agent toolchain provisioning, GPU acceleration/performance certification,
audio, clipboard/drive sharing, Wayland, and a full desktop suite.

** Work Order

1. Session prototype (nix-72d3): establish the smallest working i3/xrdp
   startup and a headless client procedure on the selected Nixpkgs source.
2. Installable GUI example (nix-l2t3): ship the self-contained tree and its
   configuration/access contract using the prototype findings.
3. Shipped-ISO smoke (nix-b1u6): install that exact revision, cold-boot, and
   verify rendering, input, and reconnect through RDP.

The first child is the entry point. Dependency edges encode that order; the
epic closes only after all three children. Use one implementation worktree
per active child and invoke the primary checkout's =bin/tickets= there.
No integration branch or PR train is required for this small epic.

** Acceptance Criteria

- The documented helper invocation installs =minimal-i3= with stdin closed
  and exits zero; the installed disk boots with the ISO detached.
- SSH works, root remains locked, and RDP starts an authenticated i3 session
  using the example's documented normal-user login.
- A real RDP client renders a terminal and delivers keyboard/mouse input;
  client-side screenshots and a guest-side observable result prove this.
- Disconnect/reconnect preserves the same running application and session.
- The original headless minimal example remains usable and its tests pass.
- Ticket evidence names exact commits, Nixpkgs source/revision, ISO checksum,
  commands, observations, artifact paths, and teardown. Large artifacts and
  ad-hoc VM/client orchestration remain untracked; dependency declarations
  and their lock file may be tracked in the repository flake.
