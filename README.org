#+TITLE: nixit

* Purpose

=nixit= turns explicit NixOS installer config into an SSH-ready ISO file and
checksum.

It does not manage the host, install Nix, create VMs, provision secrets, or own
runtime lifecycle.

* Current Status

Initial repository skeleton with host preflight, SSH-ready live ISO build,
installer config embedding, and an in-ISO =install-nixos-vm= helper.

* Contract

Given a Linux host with Nix tooling, this repo will build a bootable NixOS live
installer ISO.

The ISO contract is specified in =spec.org=.

* Repository Layout

#+begin_example
spec.org                 product contract
README.org               operator orientation
AGENTS.md                local agent instructions
bin/preflight            host readiness check
bin/build-live-installer-iso
flake.nix                optional development dependencies
flake.lock               locked Nixpkgs source
docs/                    operator documentation
examples/                example installer config trees
hosts/live-installer/    live ISO NixOS configuration
#+end_example

Generated ISOs, checksums, Nix result links, and scratch output are not tracked.

Smoke expectations are documented in =docs/smoke.org=. VM provider choice,
runtime lifecycle, networking shape, and teardown remain operator-owned.

* Preflight

Run:

#+begin_src sh
bin/preflight
#+end_src

Preflight checks:

- host OS is Linux
- host architecture is =x86_64=
- =nix-build= is available
- current directory and Nix store filesystems have rough free space
- selected =NIXPKGS_PATH= has a supported shape and resolves through Nix

Default Nixpkgs source:

#+begin_src sh
NIXPKGS_PATH=channel:nixos-26.05
#+end_src

Override examples:

#+begin_src sh
NIXPKGS_PATH=/path/to/nixpkgs bin/preflight
NIXPKGS_PATH=channel:nixos-unstable bin/preflight
MIN_FREE_GIB=16 bin/preflight
#+end_src

Preflight does not install Nix, create VMs, build an ISO, or mutate host package
state. Nix may still resolve the selected Nixpkgs source using its ordinary
store/cache behavior.

* Smoke Development Shell

The optional =rdp-smoke= development shell supplies dependencies for ad-hoc
headless GUI validation on =x86_64-linux=. Nix must already be installed with
the =nix-command= and =flakes= features enabled.

#+begin_src sh
nix develop .#rdp-smoke
printf 'NIXPKGS_PATH=%s\n' "$NIXPKGS_PATH"
bin/preflight
#+end_src

The shell provides QEMU/=qemu-img=, the FreeRDP X11 client (=xfreerdp=),
=Xvfb=/=xvfb-run=, =xdotool=, ImageMagick (=magick=), OpenSSH, coreutils,
and util-linux. It starts no services or VMs. Host KVM access remains an
operator prerequisite for accelerated VM tests.

=NIXPKGS_PATH= points to the flake's locked source, so the existing build and
preflight commands use the same Nixpkgs as the smoke tools while inside this
shell. The initial pin is the NixOS 26.05 revision used by the earlier minimal
ISO smoke: =5dfba6236110080a54247d6460bc2ff5dda939cc=. Updating it requires
changing the input revision and regenerating =flake.lock=.

VM orchestration and smoke artifacts remain outside tracked implementation
files. The shell does not replace the existing installer build interface or
install development tools into the guest image.

* Build

Run:

#+begin_src sh
bin/build-live-installer-iso
#+end_src

Default output is the ISO copied into the current directory plus =SHA256SUMS=:

#+begin_example
./nixit-live-installer-...-x86_64-linux.iso
./SHA256SUMS
#+end_example

Write to a destination directory or exact ISO filename:

#+begin_src sh
bin/build-live-installer-iso .ephemera/iso
bin/build-live-installer-iso .ephemera/iso/nixit-live.iso
#+end_src

Override the Nixpkgs source:

#+begin_src sh
NIXPKGS_PATH=/path/to/nixpkgs bin/build-live-installer-iso
NIXPKGS_PATH=channel:nixos-unstable bin/build-live-installer-iso
#+end_src

Embed installer configs:

#+begin_src sh
bin/build-live-installer-iso
CONFIG_DIR=./my-configs bin/build-live-installer-iso
#+end_src

When =CONFIG_DIR= is unset, the entire repo =examples/= tree is embedded. The
ISO therefore contains both:

#+begin_example
/etc/nixos-installer/configs/minimal/configuration.nix
/etc/nixos-installer/configs/minimal-i3/configuration.nix
#+end_example

When =CONFIG_DIR= is set, its contents replace that default tree: they are
raw-copied into =/etc/nixos-installer/configs/=, and neither repo example is
included unless the caller supplied it in =CONFIG_DIR=.

Caller configs are bring-your-own NixOS configuration trees. The build does not
template, rewrite, validate, or interpret them beyond ordinary Nix build
failures, and operators use them at their own risk.

Both examples are public fixtures for smoke testing and day-1 bootstrap. They
assume BIOS boot with GRUB installed to a disposable target VM disk at
=/dev/vda=. Real installs should bring an explicit operator-owned config.

Pass =nix-build= flags after the optional destination:

#+begin_src sh
bin/build-live-installer-iso --dry-run
bin/build-live-installer-iso .ephemera/iso --dry-run
#+end_src

The script uses =nix-build --no-out-link= internally. Nix still realizes the
build in =/nix/store=, but the user-facing artifacts are the copied ISO and
adjacent checksum file.

The live ISO enables password SSH for short-lived trusted-LAN installer use:

| user  | password |
|-------+----------|
| nixos | nixos    |
| root  | nixos    |

* Install

Boot the ISO, attach a target disk, SSH into the live system, and run:

#+begin_src sh
DISK=/dev/vda CONFIGURATION_NIX=/etc/nixos-installer/configs/minimal/configuration.nix install-nixos-vm
#+end_src

Select the remote-i3 example by changing only the explicit configuration path:

#+begin_src sh
DISK=/dev/vda CONFIGURATION_NIX=/etc/nixos-installer/configs/minimal-i3/configuration.nix install-nixos-vm
#+end_src

=DISK= is destructive. The helper partitions, formats, and mounts that disk,
copies the directory containing =CONFIGURATION_NIX= to =/mnt/etc/nixos=,
generates hardware config only when the copied tree lacks
=hardware-configuration.nix=, and runs =nixos-install --no-root-password=.

Installer configs must explicitly define their desired login and root-account
policy. The helper does not prompt for, generate, or manage root passwords.

Both repo examples enable DHCP and password SSH for the installed =nixos= user:

| user  | password | policy                                      |
|-------+----------+---------------------------------------------|
| nixos | nixos    | normal user; member of =wheel=; may use sudo |
| root  | none     | locked; direct SSH login denied              |

The live installer's separate =root:nixos= login exists only before
installation. It is not carried into either installed example.

* Remote i3 Example

=minimal-i3= adds an xrdp-created Xorg/i3 session to the installed system; it
does not turn the live installer into a GUI. Its explicit i3 config opens an
=xterm=, provides =Mod4+Return= for another terminal, =Mod4+d= for =dmenu=,
=Mod4+Shift+q= to close a window, =Mod4+Shift+e= to log out, and an i3status
bar. DejaVu fonts are installed.

The guest firewall opens only SSH. xrdp listens on guest port 3389, but that
port is not opened in the firewall. From the operator machine, carry RDP over
an SSH loopback tunnel instead:

#+begin_src sh
ssh -N -L 127.0.0.1:13389:127.0.0.1:3389 nixos@<installed-host>
#+end_src

Connect a real RDP client to =127.0.0.1:13389= as =nixos:nixos=. This is a
separate remote X session, not a mirror of a console login, and it needs no
prior console session. Disconnecting the client leaves the session running;
logging out with =Mod4+Shift+e= ends it. For reconnect, use the same user and
the same color depth as the first connection. The proven smoke used 24 bits
per pixel; xrdp's =Policy=UB= selects a session by user and bits per pixel.

Provider-specific SSH addressing, client invocation, VM lifecycle, and
teardown remain operator-owned. The provider-neutral GUI evidence procedure is
in =docs/smoke.org=.

* Non-Goals

- Installing Nix on the host.
- Managing VM lifecycle.
- Choosing VM provider tooling.
- Managing secrets.
- Provisioning SSH keys.
- Installing Codex, mise, or other agent toolchains.
